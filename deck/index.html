Mission Deep-Dive · plan mode is the gate

Read the plan. Then you're driving.

In plan mode the agent writes — in plain English — what it will do, before it does it. You edit. You push back. You approve. Then it builds. Skip the plan and you're a passenger.

claude · a real planning prompt (adapt to Aurora)


I want to redesign the Aurora product page as a single editorial
column: oversized serif name, one-line story, price, add-to-cart,
full-bleed image. Use the existing design tokens in globals.css —
do not invent colors. Plan the change first. List the files you'd
touch and what you're unsure about. Do not write code yet.
The diff is the artifact. You don't have to trust the agent — you verify, line by line, every time.
Worked prompt adapted from lesson-05-first-session. The agent returns a numbered plan and does NOT execute (it can't, in plan mode). Read it aloud, change one line live to show steering, then approve. This is the move founders skip.
Mission Deep-Dive · concept 7

Four seconds before you press return.

  1. Read the prompt back — what you wrote, not what you meant.
  2. Ask: what would the agent do if it took this literally?
  3. If the answer is "exactly what I want," press return.
  4. If it's "something I'd have to undo," add the constraint, name the file, scope it — then send.

Guardrails in the brief, not in your nerves.

From lesson-05. This is the verification habit at the input side. PUBLIC-CONTENT RULE: keep this as a practical operator habit — "read it back," "watch the diff" — NOT a somatic/embodied practice. Four seconds here saves hours of undo.

Mission Deep-Dive · guardrails before keys

Hooks: guardrails the harness enforces.

A hook is a rule the harness runs around the agent — not a request you hope it honors. Ours blocks a force-push and asks for confirmation before a deploy. Permissions are declarative, not procedural.

.claude/settings.json · PreToolUse guardrail (excerpt)


{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          { "type": "command",
            "command": ".claude/hooks/block-force-push.sh" }
        ]
      }
    ]
  }
}
harness engineering
Hooks = guardrails in the harness, not in your nerves. The block-force-push / confirm-deploy hook is the "guardrails before keys" demo. Keep it concrete: it's a real file in the repo, it really fires. This is why bounded autonomy is safe.
